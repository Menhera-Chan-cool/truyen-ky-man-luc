# Book presentation — user request 28/10/2026

## Purpose and scope
Add Ebook / Sách (Ebook / Book) immediately above Theme & background in reader settings. Ebook is the existing default and keeps its scroll/single/double preferences. Book inherits paper/ink/fonts and uses a paper frame, subtle spine, page folios, large side arrows, first/last chapter-page controls and a real folded page turn. Wide available reading area shows two columns; phone/narrow reading area shows one. Use the Hanhtrangso reader as an interaction reference, not its content/assets.

Each chapter is a separate page sequence. Turning beyond the last spread opens the following chapter at its beginning on fresh paper; previous from its first spread opens the previous chapter at its end. Never pour a new chapter into remaining space on the preceding chapter's leaf. Toolbar chapter navigation in Book also starts the selected adjacent chapter at its beginning. TOC/notes/search/listening retain their existing explicit position behavior. Page numbers are within the current chapter and adapt to font/viewport.

## Implementation boundaries
Reuse current column pagination, visible text anchors, History API, fragment navigation, footnote previews and speech. Do not concatenate chapters or mount all book HTML; only the active chapter is laid out. A printed title uses generated content in an aria-hidden empty node, preserving textContent and all saved UTF-16 offsets. Do not animate the authoritative prose transform because anchor measurement must always see the actual page. Reduced motion/e-ink remove decorative turns. Touch swipes only count short horizontal gestures outside interactive/image targets with no text selection. Plain keys retain modifiers/input/dialog guards.

Store `layout: ebook | book` with existing device settings/cookie/backup v1. Missing field in old settings/backups defaults to ebook; invalid values are rejected by backup validation. No storage schema, API permission or book-content change. One pinned dependency, page-flip 2.0.7 (MIT), is self-hosted for the explicitly requested physical page fold. PDF keeps native page/zoom UI.

Files: types.ts, reader.ts normalizer, reader-backup.ts optional legacy field, ReaderSettings.tsx, Reader.tsx, globals.css; tests in reader/backup unit suites and e2e/book-layout.spec.ts. Keep current named exports, DOM APIs and formatting. No new general framework.
