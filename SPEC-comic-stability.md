# Reading and editor stability

User approved all six recommendations in work/optimization-audit-2026-10-31.md. Preserve the approved interface, original files, VI/EN isolation and manual publication. No dependency or paid image transformation service is needed.

1. Restrict management RPC EXECUTE explicitly for PUBLIC/anon and seed/trigger functions for authenticated; preserve guarded editor/owner mutations and public read RPCs. Test Supabase-like default privileges and verify actual catalog after the migration. No book content changes.
2. Recover unsaved comic edits from a separate IndexedDB record keyed by verified account, locale and chapter. Debounced saves plus hide/page-exit flush; recover only by explicit choice and retain the server revision conflict token. No automatic public publication or silent overwrite. Clear the matching recovery snapshot on successful save/discard without erasing a newer tab's recovery. Quota/storage failure stays visible.
3. Generate bounded WebP thumbnails using installed Sharp, keep original bytes unchanged. Private derived paths are deterministic and signable only after the original asset's existing read authorization. Lazy thumbnails in editor; inspector/lightbox use originals. Backfill registered originals idempotently. No public bucket, blind deletes, paid transformation or large file body through Vercel.
4. Two bounded upload workers retain page order. Persist a successful Storage path before registration, retain registration state across retry/reload in a separate device checkpoint and reuse same path for registration failure. Server registration is idempotent under concurrent repeats. Progress names each page/stage; all workers settle before reporting failure, and publication remains unchanged on errors.
5. Comic chapter navigation uses internal router/Link, keeps current document/layout while pending, preserves position and browser Back, stops prior auto-scroll. Dynamic public data remains fresh at activation; no shared draft prefetch. On explicit neighbor intent preload only public metadata/one modest first image, respecting data-saver and limiting duplicate work. Route errors expose recovery rather than blanking the book.
6. Bounded retry/deadline for safe public reads, matching existing getBook behavior. Distinguish missing/forbidden resources from transient service failure. Preserve membership checks, validation and revision-checked writes.
